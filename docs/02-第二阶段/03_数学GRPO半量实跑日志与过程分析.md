## 一、训练配置

```bash
python grpo_math_train.py \
  --model /root/autodl-tmp/qwen_sft/models/Qwen2.5-1.5B-Instruct \
  --data  /root/autodl-tmp/qwen_grpo/data/math15_filtered.jsonl \
  --out   /root/autodl-tmp/qwen_grpo/out/grpo_math15_r3 \
  --max-steps 200 --num-generations 4 --max-completion-length 1024 \
  --batch-size 4 --grad-accum 2 \
  --lr 5e-5 --beta 0.01 --lora-r 32 --lora-alpha 64
```

| 参数 | 取值 | 说明 |
|---|---|---|
| 基座 | Qwen2.5-1.5B-Instruct | 未做 SFT，直接 GRPO |
| 方法 | LoRA（r=32, α=64, 全部 7 个投影层） | **不是全参** |
| 学习率 | 5e-5 | 第一轮 1e-5 时 KL<0.001、学不动 |
| beta（KL 惩罚） | 0.01 | 第一轮 0.04 时策略被摁死在原地 |
| `num_generations` | 4 | 组内 4 条 rollout |
| `max_completion_length` | 1024 | 第一轮 640 时 100% 截断 |
| 训练数据 | 331 题（难度筛选后） | 见第三节 |
| 硬件 | RTX PRO 6000 Blackwell 96GB 单卡 | 训练期显存 16.2 GB |

**奖励设计（与评测判分严格同构）**：

| 情形 | 奖励 |
|---|---|
| 答案正确 | +1.0 |
| 有 `\boxed{}` 但答案错 | +0.1 |
| 抓不到答案 | −0.2 |

> 奖励函数直接复用评测器 `math_eval.py` 的抽取/判分代码，并用单测确认「奖励=1.0 的样本」与「评测判对的样本」**完全一致**。这是本实验区别于第一阶段的关键：**训练涨的就是评测测的**。

## 三、难度筛选：本实验最关键的前置步骤

![判分器质量验证](../../assets/math15_extraction.png)

**做法**：先用 base 对 1,200 题池**每题采样 2 次**，只保留 `pass@2 = 0.5` 的题（即一错一对）。

| 项 | 值 |
|---|---|
| 保留 / 跳过 | **331 / 869**（保留率 27.6%） |
| 保留题难度 | Level 1 (56) / Level 2 (128) / Level 3 (147) |
| 学科覆盖 | Algebra 87、Prealgebra 78、Precalculus 42、Intermediate Algebra 40、Number Theory 37、C&P 30、Geometry 17 |
| pass@2 分布 | **全部为 0.5** |

**为什么必须做**：GRPO 靠**组内奖励差异**产生梯度。若某题 4 条 rollout 全错，组内方差为 0、该题不贡献任何梯度。

实测支撑：base 在 **AIME 上仅 3.3%**（90 题对 3 题），那类难度确实不可用；筛选后每题都是 `pass@2=0.5`，组内必定有对有错。

## 四、四个值得注意的现象

### 1. 零方差比例 0.545 —— 约一半的算力没产生梯度

```text
frac_reward_zero_std  均值 0.545
```

即约 **54.5% 的 prompt 组，4 条 rollout 分数完全相同**（全对或全错），这些组不产生优势信号。

这与难度筛选的设计目标有出入：筛选保证了 `pass@2=0.5`，但**训练时是 4 条 rollout**，全对/全错的概率自然更高。要压低它，两条路：

```text
调大 num_generations（4 -> 8）       组更大，出现分歧的概率更高
换区分度更好的奖励                  当前奖励只有三档（+1 / +0.1 / -0.2），粒度粗
```

第二点值得单独说：**奖励只有三档**，意味着部分正确（如过程对、最后一步算错）与完全不会得到相同分数，这本身压缩了组内差异。第一阶段的教训是"奖励不针对目标"，本轮的教训更细：**奖励不仅要针对目标，还要有足够粒度**。

### 2. 前两轮失败：训练侧 prompt 没套 chat 模板

这是本次最贵的一课，值得完整记录。

**症状**：

```text
第 1 轮 (lr 1e-5, beta 0.04, 上限 640)
    截断比 1.00      平均生成长度 640（正好等于上限）
    训练集准确率 46.9% -> 46.9%（完全没动）
    KL 0.0006（策略几乎静止）
第 2 轮 (lr 5e-5, beta 0.01, 上限 1024)
    截断比 1.00      平均生成长度 1024（顶格）
    训练集准确率 46.9% -> 32.0%（反而更差）
    KL 升到 0.0043（策略动了，但往坏处动）
```

**根因**：给 GRPO 喂的是**纯文本 prompt**（没套 chat 模板）。Qwen2.5-Instruct 是在 ChatML 上微调的，收到裸文本会当成预训练语料**续写**——实测会伪造 `Human:` 轮次、无限生成直到撞上限。

**诊断对照实验**（同一批题，只改提示词方式）：

| 提示词方式 | 生成长度 | 是否收尾 |
|---|---|---|
| **chat 模板** | 67 / 295 token | **自然收尾，答案正确** |
| 裸文本 | 1024（顶格） | 伪造 `Human:` 轮次，无终止 |

**修复**：把 prompt 存成对话格式（`[{"role":"user","content":...}]`），TRL 内部的 `maybe_apply_chat_template()` 会自动套模板。

**修复后**：截断比 **1.00 → 0.00**，训练集准确率 **32% → 66%**。

> 一个重要的边界：**评测器始终使用 chat 模板**，所以基线与评测数字从头到尾都是对的。**只有训练侧出错**——这解释了为什么"训练日志显示在学、评测却不动"这个假象能持续两轮。

### 3. 学习率与 KL 惩罚的联合调参

第一轮的组合是"策略学不动"的典型：

```text
lr 1e-5 + beta 0.04        KL 0.0006      策略几乎静止
lr 5e-5 + beta 0.01        KL 0.018       有实质位移且收敛
```

**关键在于比例**：奖励幅度只有 ±1，而 β=0.04 的 KL 惩罚相对过强，会把策略摁在原处。调低 β 并提高 lr 后，KL 才升到有意义的量级。

### 4. 判分器质量：格式合规率 93.4%

```text
GRPO  MATH-500     boxed 467/500 = 93.4%     none 0
GRPO  AIME         boxed  78/90  = 86.7%     none 0
```

`none`（判分器完全抓不到答案）为 **0**，说明奖励信号没有因为判分失败而丢失。

## 五、耗时与资源

### 总账

```text
总步数      200
总耗时      3,363 秒 = 56.0 分钟
平均        16.8 秒/步
```

**预估偏差**：开跑时按前几步测到约 12-17 秒/步，外推得 40-55 分钟，实际 56 分钟，**在估算区间内**。

### 显存

```text
训练期峰值    16.2 GB / 96 GB
```

LoRA 只训练约 0.5% 的参数，所以**优化器状态极小**——这是 16 GB 的主因。作为对照，全参 GRPO 的估算需求约为 40-50 GB（权重 2.9 + 梯度 2.9 + Adam 状态 5.8 + 参考模型 2.9 + 激活 10-20 + KV cache 1-2），96 GB 同样跑得下，但**本轮没实测**。

### GPU 利用率

```text
训练期利用率   93%
```

瓶颈在自回归生成的 rollout，而非参数更新——这是 GRPO 这类在线 RL 的固有特征。

### 评测耗时（单卡，用于解释总时长）

| 阶段 | 题数 | 耗时 |
|---|---|---|
| 基线 MATH-500 | 500 | 约 57 分钟 |
| 基线 AIME | 90 | 约 19 分钟 |
| 复评 MATH-500 | 500 | 约 103 分钟 |
| 复评 AIME | 90 | 约 18 分钟 |

**评测（197 分钟）比训练（56 分钟）贵 3.5 倍**。瓶颈同样是自回归推理：500 题 × 约 400 token 推理链 ≈ 12 秒/题。下次提速的方向：vLLM 批量推理（预期 3-5×）或减少题量。

## 七、复现

```bash
# 1) 难度筛选（先做，否则训练无梯度）
python difficulty_filter.py --model <base> --pool math_train_raw.jsonl \
  --out math15_filtered.jsonl --num 1200 --k 2 --lo 0.1 --hi 0.9 --levels 1,2,3

# 2) 训练（注意 prompt 必须走对话格式，见第四节第 2 条）
python grpo_math_train.py --model <base> --data math15_filtered.jsonl \
  --out out/grpo_math15_r3 --max-steps 200 --lr 5e-5 --beta 0.01 \
  --max-completion-length 1024 --num-generations 4

# 3) 复评（与基线同一套题、同一判分口径）
python math_eval.py --model <base> --adapter out/grpo_math15_r3 \
  --bench math500 --tag grpo --no-think --out math15_results.csv
```
